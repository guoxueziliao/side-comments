# 10-开发顺序与验收标准

## 目标

本文件用于指导 MVP 实施顺序。

原则：

> 先打稳数据层和加载策略，再做交互和 UI。

每个阶段完成后再进入下一阶段，避免后期因为数据结构、性能或迁移策略返工。

## 阶段 1：插件骨架

实现内容：

- `manifest.json`
- `main.ts`
- `styles.css`
- 基础插件类
- 基础设置加载和保存
- Obsidian 第三方插件设置页

验收标准：

- 插件可以被 Obsidian 加载。
- 插件可以启用和禁用。
- 设置页可以打开。
- 设置项可以读取默认值。
- 禁用插件后没有残留 DOM。

不要求：

- 不要求实现批注。
- 不要求实现侧边栏。
- 不要求实现正文标记。

## 阶段 2：数据层

实现内容：

- `.obsidian-side-comments/` 目录创建。
- `manifest.json` 全局元信息写入。
- sidecar 文件路径 hash。
- SHA-256 文件名。
- hash 前两位分桶。
- 当前文档 sidecar 读写。
- `schemaVersion` 字段。
- sidecar JSON 默认结构。
- 文件重命名迁移。
- lazy migration 框架。

验收标准：

- 打开文档时可以计算对应 sidecar 路径。
- 新建批注时可以写入对应 sidecar。
- 读取当前文档时只读取当前 sidecar。
- 没有 sidecar 时返回空文档结构。
- 文件重命名后，旧 sidecar 迁移到新路径。
- 重命名迁移不扫描全库。
- `schemaVersion` 正确写入。
- 旧 schema 可以通过 lazy migration 升级。
- 迁移前会为当前 sidecar 写入备份。

不允许：

- 不允许启动时扫描 `.obsidian-side-comments/files/`。
- 不允许把所有批注写入一个大 JSON。
- 不允许把批注写入 Markdown 正文。

## 阶段 3：加载缓存层

实现内容：

- 当前文档加载。
- 当前文档 sidecar 缓存。
- 内存 LRU cache。
- 最近预览缓存框架。
- 空 sidecar 处理。
- sidecar 读取失败处理。

验收标准：

- 启动插件不读取全库 sidecar。
- 打开哪篇文档，只加载哪篇 sidecar。
- 最近打开过的文档可以从 LRU cache 返回。
- LRU cache 超过上限后淘汰旧文档。
- 没有批注时侧边栏可显示空状态。
- sidecar 读取失败时不影响其他文档。

默认参数：

```ts
maxCachedDocuments = 100;
```

## 阶段 4：选区与浮动工具条

实现内容：

- 监听 Markdown 正文选区。
- 显示浮动工具条。
- 工具条提供四个入口：
  - 高亮
  - 下划线
  - 删除线
  - 评论
- 创建批注数据。
- 完全相同位置去重。

入口行为：

| 按钮 | 默认行为 |
|---|---|
| 高亮 | 创建 `highlight + yellow` 卡片 |
| 下划线 | 创建 `underline + blue` 卡片 |
| 删除线 | 创建 `strikethrough + red` 卡片 |
| 评论 | 创建 `highlight + purple` 卡片 |

验收标准：

- 选中文本后出现工具条。
- 未选中文本时不显示工具条。
- 四个按钮创建的类型和颜色正确。
- 批注写入 sidecar。
- Markdown 原文不发生变化。
- 完全相同 `startOffset/endOffset` 不重复创建。
- 相同文本不同位置允许创建。
- 部分重叠选区允许创建。

## 阶段 5：正文视觉标记渲染

实现内容：

- 编辑模式 CodeMirror Decoration 渲染。
- 阅读视图 DOM 投影渲染。
- 三种标记：
  - highlight
  - underline
  - strikethrough
- resolved 弱化显示。
- orphaned 不渲染。
- hover 提示。

验收标准：

- 高亮显示半透明背景色。
- 下划线显示彩色下划线。
- 删除线显示彩色删除线并轻微淡化。
- 标记不改变 Markdown 原文。
- 标记不导致行高明显变化。
- 标记不造成正文抖动。
- `resolved` 标记弱化显示。
- `orphaned` 不在正文渲染。
- hover 显示 `查看批注`。

## 阶段 6：侧边栏和卡片

实现内容：

- 右侧阅读摘录管理面板。
- 当前文档卡片列表。
- 卡片紧凑展示。
- 原文摘录最多 3 行。
- 批注内容最多 3 行。
- 展开和收起。
- 编辑态。
- 状态切换。
- 删除二次确认。

验收标准：

- 侧边栏只显示当前文档批注。
- 卡片默认按正文从上到下排序。
- `orphaned` 卡片显示在底部。
- 卡片显示标记类型、颜色、状态和时间。
- 无批注内容时显示 `未填写批注`。
- 点击编辑后输入框获得焦点。
- `Enter` 保存。
- `Shift + Enter` 换行。
- 中文输入法组合态下 `Enter` 不误保存。
- `Esc` 取消编辑。
- 删除前有二次确认。
- 删除不会修改 Markdown 正文。

## 阶段 7：搜索、筛选和空状态

实现内容：

- 当前文档搜索。
- 标记类型筛选。
- 状态筛选。
- 计数显示。
- 空状态文案。

验收标准：

- 搜索范围是原文摘录和批注内容。
- 中文按包含匹配。
- 英文大小写不敏感。
- 可按类型筛选：全部 / 高亮 / 下划线 / 删除线。
- 可按状态筛选：全部 / 未处理 / 已处理 / 已失联。
- 不提供颜色筛选。
- 不提供全库筛选。
- 无搜索或筛选时显示：`当前文档 · 共 12 条批注`。
- 有搜索或筛选时显示：`当前文档 · 共 12 条 · 当前显示 4 条`。
- 无结果时显示：`没有匹配的批注`。

## 阶段 8：双向定位

实现内容：

- 点击侧边栏卡片跳回正文。
- 点击正文标记定位侧边栏卡片。
- 视觉反馈。

验收标准：

- 点击卡片后，正文滚动到对应位置。
- 正文目标位置短暂闪烁或高亮。
- 点击正文标记后，侧边栏打开。
- 侧边栏滚动到对应卡片。
- 对应卡片短暂闪烁或描边 1 秒。
- 当前文档内定位稳定。

## 阶段 9：锚点恢复

实现内容：

- offset 直接命中。
- selectedText + prefix/suffix 上下文恢复。
- 高阈值 fuzzy match。
- 恢复失败标记 orphaned。
- 修改后 debounce。

验收标准：

- `source.slice(startOffset, endOffset) === selectedText` 时直接命中。
- offset 不准时，可以通过上下文恢复位置。
- fuzzy match 置信度 `>= 0.85` 时自动恢复。
- fuzzy match 置信度 `< 0.85` 时不自动恢复。
- 恢复失败后 `status = "orphaned"`。
- orphaned 批注不删除。
- orphaned 批注不渲染正文标记。
- orphaned 批注显示在侧边栏底部。
- 当前文档修改后 800ms debounce 再执行恢复。
- 不做启动全库恢复。
- 不做后台批量恢复。

## 阶段 10：性能验收

验收重点：

- 启动时不扫描全库。
- 启动时不读取所有 sidecar。
- 当前文档加载只读取当前 sidecar。
- 当前文档几百条批注仍可编辑和滚动。
- 文档修改不会每个字符触发恢复。
- sidecar 分桶有效。
- 几十万 sidecar 文件存在时，不因启动读取而卡死。
- LRU cache 上限生效。

建议测试场景：

1. 空 vault。
2. 单文档 1 条批注。
3. 单文档 100 条批注。
4. 单文档 500 条批注。
5. 大量 sidecar 文件存在但不打开对应文档。
6. 重命名带批注文档。
7. 修改原文导致批注可恢复。
8. 修改原文导致批注失联。

## 阶段 11：MVP 收口

收口检查：

- Markdown 原文未被写入批注语法。
- `.obsidian-side-comments/` 数据结构符合规格。
- 设置页符合 MVP 设置项。
- 文档级 `schemaVersion` 正确。
- lazy migration 可运行。
- 删除、重命名、失联都有明确处理。
- 第一版不包含 AI、PDF、全库筛选、全库搜索、导出 Markdown。

MVP 完成标准：

> 用户可以在当前 Markdown 文档中选中文本，创建高亮、下划线、删除线或评论；批注不污染正文，保存在 sidecar；右侧面板可管理当前文档批注；正文和侧栏可以双向定位；文档修改后能安全恢复或标记失联；启动和加载策略适配大库。

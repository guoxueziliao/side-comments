# 01-数据存储与结构

## 顶层目录

批注数据放在：

```text
.obsidian-side-comments/
```

## 分片结构

为了支撑几十万篇笔记，sidecar 文件不能全部平铺在一个目录下。

推荐结构：

```text
.obsidian-side-comments/
  manifest.json
  files/
    00/
    01/
    ...
    ff/
```

文件路径通过 hash 映射到桶里。

例如：

```text
filePath -> hash(filePath) -> 前两位作为桶名 -> files/ab/abxxxx.json
```

这样即使未来有几十万篇带批注的笔记，也不会让单个目录承载过多文件。

## manifest 元信息

`.obsidian-side-comments/manifest.json` 只记录全局元信息，不参与全库索引，不要求扫描全部 sidecar。

结构：

```json
{
  "schemaVersion": 1,
  "pluginVersion": "0.1.0",
  "updatedAt": "2026-05-20T00:00:00.000Z"
}
```

## sidecar 文件命名和路径 hash 规则

sidecar 文件名由规范化后的 vault 相对路径计算 SHA-256 得到。

hash 输入：

```text
hashInput = normalizedVaultRelativePath
```

示例：

```text
01-文档/2026/05/2026-05-20_xxx.md
```

路径标准化规则：

- 使用 `/` 作为路径分隔符。
- 不使用 `\`。
- JSON 内保留原始大小写路径。
- 计算 hash 时可以统一转小写，避免 Windows 大小写问题。

hash 算法：

```text
SHA-256
```

文件名使用完整 SHA-256 hex：

```text
ab3f...完整hex.json
```

分桶规则：

```text
.obsidian-side-comments/files/ab/ab3fxxxx.json
```

其中 `ab` 来自 hash 前两位。

sidecar JSON 内必须保存真实路径：

```ts
filePath: "01-文档/2026/05/xxx.md"
```

文件重命名处理：

1. 根据新路径计算新的 sidecar 路径。
2. 将旧 sidecar 迁移到新 sidecar。
3. 更新 sidecar JSON 内的 `filePath`。
4. 删除旧 sidecar。
5. 不扫描全库。

冲突处理：

- SHA-256 理论上不需要考虑冲突。
- MVP 不做 hash 冲突处理。

## 数据结构

### 文档级 sidecar

```ts
interface SideCommentDocument {
  schemaVersion: 1;
  filePath: string;
  fileHash: string;
  updatedAt: string;
  comments: SideComment[];
}
```

### 单条批注

```ts
interface SideComment {
  id: string;

  anchor: {
    startOffset: number;
    endOffset: number;
    selectedText: string;
    prefix: string;
    suffix: string;
  };

  mark: {
    type: "highlight" | "underline" | "strikethrough";
    color: "yellow" | "blue" | "red" | "green" | "purple";
  };

  note: {
    content: string;
    createdAt: string;
    updatedAt: string;
  };

  status: "active" | "resolved" | "orphaned";
}
```

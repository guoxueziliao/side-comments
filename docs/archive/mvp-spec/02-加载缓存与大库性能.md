# 02-加载缓存与大库性能

## 大库性能原则

目标场景是几十万篇笔记，每篇可能有 2-3 条批注。

插件必须按大库设计。

核心原则：

> 看什么加载什么，用什么加载什么。

具体规则：

- 启动时不扫描全库
- 启动时不加载所有批注
- 默认不遍历 `.obsidian-side-comments/files/`
- 打开哪篇 Markdown，只加载哪篇对应的 sidecar
- 当前文档批注实时渲染
- 当前文档侧边栏只显示当前文档批注
- 已打开过的文档可以进入内存 LRU cache
- 可以保存最近加载过的轻量预览
- 预览数据不等于完整批注加载
- 全库搜索不进 MVP
- 全库搜索未来需要单独设计索引和渐进加载

## 渐进加载设计

插件采用按需水合设计。

### 启动阶段

启动时只加载：

- 插件设置
- 必要的运行状态

不加载：

- 全库批注
- 所有 sidecar
- 全库索引全文内容

### 当前文档加载

打开 Markdown 文件时：

```text
当前文件路径 -> hash -> 找到对应 sidecar JSON -> 只加载这一份
```

然后：

- 渲染当前文档正文标记
- 渲染当前文档侧边栏卡片
- 支持当前文档搜索、筛选和排序

### 内存缓存

已经打开过的文档可以进入内存 LRU cache。

建议初始参数：

```ts
maxCachedDocuments = 100;
```

后续可以根据实际性能调整到 300。

### 最近预览缓存

可以维护一个轻量预览缓存，例如：

```text
.obsidian-side-comments/cache/recent.json
```

只保存最近加载过的摘要信息：

```ts
interface RecentPreviewItem {
  filePath: string;
  commentCount: number;
  updatedAt: string;
  preview: {
    id: string;
    selectedTextPreview: string;
    notePreview: string;
    markType: string;
    color: string;
  }[];
}
```

用途：

- 让用户看到最近处理过的批注概览
- 不需要真实加载所有批注文件
- 点击、编辑、跳转时再加载完整 sidecar

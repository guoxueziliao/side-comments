# 05-交互流程与编辑规则

## 交互主流程

MVP 主流程：

1. 用户在 Markdown 正文中选中文本。
2. 插件显示浮动工具条。
3. 用户选择高亮、下划线、删除线或评论。
4. 插件根据入口创建对应类型和默认颜色的卡片。
5. 新卡片自动进入批注编辑状态。
6. 用户可以填写批注内容，也可以保留空批注。
7. 插件生成 sidecar 批注数据。
8. 正文显示对应视觉标记。
9. 右侧阅读摘录管理面板出现对应卡片。
10. 用户点击卡片，可以跳回正文位置。
11. 用户点击正文标记，可以定位到侧边栏卡片。
12. 用户可以在卡片内编辑、删除、设为已处理。

## 浮动工具条 MVP 入口

| 按钮 | 默认行为 |
|---|---|
| 高亮 | 创建 `highlight + yellow` 卡片，并进入批注编辑 |
| 下划线 | 创建 `underline + blue` 卡片，并进入批注编辑 |
| 删除线 | 创建 `strikethrough + red` 卡片，并进入批注编辑 |
| 评论 | 创建 `highlight + purple` 卡片，并进入批注编辑 |

说明：

- 评论不是独立标记类型，底层仍使用 `highlight` 作为正文锚点视觉层。
- 评论默认使用 `purple`，避免占用 `yellow` 的重点高亮语义。
- MVP 工具条不放颜色选择器。
- 创建后可以在卡片内调整颜色。

## 批注编辑规则

批注输入框采用快速评论式交互。

核心规则：

> Enter 保存，Shift + Enter 换行。

具体行为：

| 操作 | 行为 |
|---|---|
| `Enter` | 保存批注 |
| `Shift + Enter` | 换行 |
| `Ctrl + Enter` | 保存批注 |
| `Cmd + Enter` | 保存批注 |
| 点击保存 | 保存批注 |
| `Esc` | 取消编辑 |
| 点击取消 | 取消编辑 |
| 失焦 | 不自动保存 |

补充规则：

- 中文输入法组合态下，`Enter` 不能触发保存。
- 需要判断 `event.isComposing`，或监听 `compositionstart` / `compositionend`。
- 空批注允许保存，因为用户可能只想划线，不写评论。
- 失焦不自动保存，避免用户点击正文查看上下文时误保存半成品。
- 切换编辑目标前，如果当前批注有未保存内容，需要先保存或取消。
- 输入框 placeholder 建议为：`写下批注... Enter 保存，Shift+Enter 换行`

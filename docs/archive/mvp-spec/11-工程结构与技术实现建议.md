# 11-工程结构与技术实现建议

## 目标

本文件用于指导插件工程实现，避免把数据层、锚点层、渲染层和 UI 层混在一起。

实现原则：

> 数据层先稳定，视图层只消费状态，不直接操作文件系统。

## 技术栈

建议：

- Obsidian Plugin API
- TypeScript
- CodeMirror 6 Extension
- Obsidian 原生 DOM API
- CSS
- esbuild

MVP 不建议引入：

- React
- Vue
- Svelte
- 状态管理库
- 数据库
- Web Worker
- AI SDK
- PDF 相关依赖

原因：

- MVP 交互复杂度可控。
- Obsidian 插件原生 API 已经足够。
- 减少构建和调试复杂度。
- 先保证 sidecar 数据结构、锚点恢复和大库性能。

## 模块职责

### `main.ts`

职责：

- 插件入口。
- 加载设置。
- 初始化 store。
- 注册 CodeMirror 扩展。
- 注册侧边栏 ItemView。
- 注册命令。
- 注册事件。
- 注册设置页。

不做：

- 不直接拼 sidecar 路径。
- 不直接实现锚点恢复算法。
- 不直接渲染卡片细节。

### `src/types.ts`

职责：

- 统一定义核心类型。

包括：

```ts
type MarkType = "highlight" | "underline" | "strikethrough";
type MarkColor = "yellow" | "blue" | "red" | "green" | "purple";
type SideCommentStatus = "active" | "resolved" | "orphaned";
```

以及：

- `SideCommentDocument`
- `SideComment`
- `TextAnchor`
- `PluginSettings`
- `RecentPreviewItem`

### `src/settings/`

职责：

- 默认设置。
- 设置读写。
- Obsidian `PluginSettingTab`。

MVP 设置项：

- 创建批注后自动打开侧边栏。
- 显示已处理批注的正文标记。
- 内存缓存文档数。
- 文档修改后恢复延迟。
- 数据目录只读展示。

### `src/storage/pathHash.ts`

职责：

- vault 相对路径标准化。
- SHA-256 hash。
- sidecar 分桶路径计算。
- backup 路径计算。

输入：

```ts
filePath: string
```

输出：

```ts
.obsidian-side-comments/files/ab/abxxxx.json
```

### `src/storage/sidecarStore.ts`

职责：

- 当前文档 sidecar 读写。
- 空文档结构生成。
- 写入 manifest。
- 文件重命名迁移。
- 与 migration 模块协作。
- 与 LRU cache 协作。

不做：

- 不扫描全库。
- 不渲染 UI。
- 不直接操作 CodeMirror。

### `src/storage/migration.ts`

职责：

- 根据 `schemaVersion` 执行 lazy migration。
- 迁移前备份当前 sidecar。
- 链式执行迁移。
- 保证迁移幂等。

接口建议：

```ts
async function migrateDocument(
  document: unknown,
  context: MigrationContext
): Promise<SideCommentDocument>
```

### `src/storage/lruCache.ts`

职责：

- 最近加载文档缓存。
- 上限默认 100。
- 超出后淘汰最久未使用项。

缓存 key：

```ts
normalizedVaultRelativePath
```

### `src/storage/recentPreview.ts`

职责：

- 维护最近加载过的轻量预览。
- 不保存完整批注正文。
- 不替代 sidecar。

MVP 可以先保留接口，必要时后续实现。

### `src/anchor/textAnchor.ts`

职责：

- 从选区创建锚点。
- 保存 `startOffset`、`endOffset`、`selectedText`、`prefix`、`suffix`。

上下文长度：

```ts
prefixLength = 40;
suffixLength = 40;
```

### `src/anchor/relocate.ts`

职责：

- 执行锚点恢复流程。
- 直接 offset 命中。
- 上下文精确匹配。
- 高阈值 fuzzy match。
- 失败标记 orphaned。

阈值：

```text
contextScore >= 0.75
fuzzyConfidence >= 0.85
```

### `src/anchor/fuzzyMatch.ts`

职责：

- 提供模糊匹配函数。
- 返回候选位置和置信度。

要求：

- 只对当前文档执行。
- 不做全库搜索。
- 不低置信度自动恢复。

### `src/editor/selectionToolbar.ts`

职责：

- 监听选区。
- 显示浮动工具条。
- 提供四个入口：
  - 高亮
  - 下划线
  - 删除线
  - 评论

不做：

- 不直接写 sidecar。
- 不渲染侧边栏卡片。

工具条回调交给主插件或 controller 处理。

### `src/editor/editorExtension.ts`

职责：

- 注册 CodeMirror 6 ViewPlugin。
- 读取当前文档批注。
- 构建 Decoration。
- 捕捉编辑器选区 offset。

使用 API：

- `ViewPlugin`
- `Decoration`
- `DecorationSet`
- `RangeSetBuilder`
- `EditorView`
- `editorInfoField`

### `src/editor/markDecorations.ts`

职责：

- 将 `SideComment` 转成 CodeMirror Decoration。
- 处理不同 mark type 的 CSS class。
- 处理 resolved 弱化。
- 跳过 orphaned。

视觉层级：

```text
strikethrough > underline > highlight
```

### `src/editor/readingViewRenderer.ts`

职责：

- 在 Reading View 中做 DOM 投影。
- 遍历文本节点。
- 根据锚点定位文本范围。
- 包装视觉标记。
- 避免重复包装。
- 清理旧标记。

注意：

- 不修改 Markdown 文件。
- 不处理 PDF。
- 不处理全库。

### `src/views/sidebarView.ts`

职责：

- Obsidian `ItemView`。
- 当前文档批注列表。
- 搜索。
- 筛选。
- 正文顺序排序。
- 空状态。
- 卡片事件分发。

不做：

- 不直接计算 sidecar hash。
- 不直接执行 fuzzy match。

### `src/views/commentCard.ts`

职责：

- 单张卡片渲染。
- 展开/收起。
- 编辑态。
- 状态按钮。
- 删除确认。

编辑规则：

- `Enter` 保存。
- `Shift + Enter` 换行。
- `Ctrl/Cmd + Enter` 保存。
- `Esc` 取消。
- 中文输入法组合态不误保存。

### `src/views/emptyStates.ts`

职责：

- 统一空状态文案。

文案：

- 打开一篇 Markdown 笔记后，可以在这里管理正文批注
- 选中正文后添加高亮、下划线、删除线或评论
- 没有匹配的批注
- 批注数据读取失败，请检查 `.obsidian-side-comments/`
- 有批注找不到原文位置，仍保留在列表底部

### `src/commands/commands.ts`

职责：

- 注册命令。

MVP 命令建议：

- 打开正文批注面板。
- 对当前选区添加高亮。
- 对当前选区添加下划线。
- 对当前选区添加删除线。
- 对当前选区添加评论。

快捷键默认可以不绑定，避免和用户现有快捷键冲突。

### `src/utils/`

职责：

- 通用工具。

包括：

- `debounce.ts`
- `dom.ts`
- `time.ts`

## 数据流

创建批注数据流：

```text
用户选中文本
-> selectionToolbar 触发入口
-> editorExtension 或 Obsidian Editor 获取 offset
-> textAnchor 创建锚点
-> sidecarStore 加载当前文档
-> 检查完全相同位置是否已存在
-> 写入 SideComment
-> 保存 sidecar
-> 刷新正文 Decoration
-> 刷新 sidebarView
-> 新卡片进入编辑态
```

打开文档数据流：

```text
file-open
-> sidecarStore 加载当前 sidecar
-> migration 检查 schemaVersion
-> 必要时迁移并写回
-> relocate 检查锚点
-> 更新 cache
-> 渲染正文标记
-> 刷新侧边栏
```

修改文档数据流：

```text
vault modify
-> debounce 800ms
-> 只处理当前或被修改文件
-> relocate 当前文档批注
-> 保存更新后的 sidecar
-> 刷新正文标记和侧边栏
```

## Obsidian API 使用建议

需要使用：

- `Plugin`
- `PluginSettingTab`
- `ItemView`
- `WorkspaceLeaf`
- `MarkdownView`
- `TFile`
- `Notice`
- `MarkdownRenderer`，仅当批注内容需要 Markdown 渲染时
- `this.registerEditorExtension`
- `this.registerView`
- `this.registerEvent`
- `this.app.vault.on("rename")`
- `this.app.vault.on("modify")`
- `this.app.workspace.on("file-open")`

## CodeMirror 6 使用建议

编辑模式标记使用 CodeMirror 6。

核心 API：

- `ViewPlugin`
- `ViewUpdate`
- `Decoration`
- `DecorationSet`
- `RangeSetBuilder`
- `EditorView`
- `editorInfoField`

原则：

- Decoration 只画视觉效果。
- 不 dispatch 文档变更。
- 不写入 Markdown。
- 每次只对当前 editor view 构建当前文档 decorations。

## CSS 命名建议

统一前缀：

```text
side-comments-
```

示例：

- `side-comments-mark`
- `side-comments-mark--highlight`
- `side-comments-mark--underline`
- `side-comments-mark--strikethrough`
- `side-comments-mark--resolved`
- `side-comments-sidebar`
- `side-comments-card`
- `side-comments-toolbar`

避免使用过于通用的 class 名，防止污染 Obsidian 主题。

## 实现边界

MVP 重点：

- 数据可靠
- 不污染正文
- 当前文档可用
- 大库不启动扫描
- 锚点恢复保守

MVP 不追求：

- 最华丽 UI
- 全库搜索
- 导出系统
- AI
- PDF
- 多人协作

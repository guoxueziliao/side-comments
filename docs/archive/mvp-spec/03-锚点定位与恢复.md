# 03-锚点定位与恢复

## 锚点策略

每条批注保存文本锚点，用于定位原文。

锚点包含：

- `startOffset`
- `endOffset`
- `selectedText`
- `prefix`
- `suffix`

目的：

- 正常情况下通过 offset 快速定位
- 文档修改后通过 selectedText 重新查找
- 文本重复时通过 prefix 和 suffix 判断上下文
- 找不到时标记为 orphaned，而不是删除批注

基本规则：

- 文档打开时加载当前文档批注
- 渲染正文视觉标记
- 文档修改后只对当前或被修改文件尝试重定位
- 重定位失败时，保留批注数据并标记为已失联

## 锚点恢复流程

锚点恢复按四级流程执行。

### 直接位置命中

先检查原始 offset 是否仍然准确：

```ts
source.slice(startOffset, endOffset) === selectedText
```

如果一致：

```text
confidence = 1.0
status 保持 active 或 resolved
```

这是最快路径。

### 上下文精确匹配

如果 offset 不准，则查找 `selectedText` 的所有出现位置，并用 `prefix` 和 `suffix` 比较上下文。

上下文长度：

```text
prefixLength = 40
suffixLength = 40
```

命中规则：

```text
selectedText 相同
并且 prefix/suffix 综合得分 >= 0.75
```

命中后更新新的 `startOffset` 和 `endOffset`。

### 高阈值模糊匹配

如果上下文精确匹配失败，再执行 fuzzy match。

阈值规则：

| 置信度 | 行为 |
|---|---|
| `>= 0.85` | 自动恢复位置 |
| `0.65 - 0.85` | 不自动恢复，标记为已失联 |
| `< 0.65` | 标记为已失联 |

MVP 不做低置信度自动恢复。

原则：

> 错绑比失联更糟。

### 恢复失败

恢复失败时：

```ts
status = "orphaned";
```

处理规则：

- 不删除批注。
- 不渲染正文标记。
- 侧边栏底部显示。
- 卡片显示“原文失联”。
- 保留原始 `selectedText`、`prefix` 和 `suffix`。
- 手动重新绑定放到 v0.2，不进入 MVP。

## 锚点恢复触发时机

只在这些时候做恢复：

- 打开当前文档时。
- 当前文档被修改后。
- 用户点击已失联卡片时，可以尝试重新检测一次。

不做：

- 启动时全库恢复。
- 全库扫描恢复。
- 后台批量恢复。

文档修改后的恢复需要 debounce，避免每个字符都触发恢复。

建议：

```text
debounce = 800ms
```

用户停止输入 800ms 后，只对当前文档做一次恢复。
